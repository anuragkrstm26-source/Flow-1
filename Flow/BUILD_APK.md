# Build Flow APK with GitHub Actions

This repository is configured to build Flow without Android Studio, a locally installed Android SDK, or a locally installed Gradle command. GitHub Actions installs Java 17, the Android SDK packages, and the Gradle distribution referenced by the committed Gradle Wrapper.

## 1. Upload or push the project to GitHub

### Option A: Upload in the GitHub website

1. Create a new GitHub repository. A blank repository is simplest; do not add another README or `.gitignore`.
2. Open the repository and choose **Add file → Upload files**.
3. Upload the contents of this project, including:
   - `.github/workflows/build-apk.yml`
   - `gradlew`
   - `gradlew.bat`
   - `gradle/wrapper/gradle-wrapper.jar`
   - `gradle/wrapper/gradle-wrapper.properties`
   - `settings.gradle`, `build.gradle`, and the `app/` directory
4. Commit the files to `main`.

GitHub Actions only sees the workflow after the `.github/workflows/build-apk.yml` file is committed to the repository.

### Option B: Push with Git

From the project root:

```bash
git init
git add .
git commit -m "Prepare Flow GitHub Actions APK build"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/YOUR_REPOSITORY.git
git push -u origin main
```

Replace `YOUR_USERNAME` and `YOUR_REPOSITORY` with the GitHub repository owner and name. If the repository already has Git history, use `git add .`, `git commit`, and `git push` instead of running `git init`.

Keep the executable bit on `gradlew`. GitHub Actions also runs `chmod +x ./gradlew` before building, so the workflow repairs the bit if a browser upload removed it.

## 2. Start the GitHub Actions build

The workflow starts automatically when you push to `main` or `master`, or open a pull request.

To start it manually:

1. Open the repository on GitHub.
2. Open the **Actions** tab.
3. Select **Build Flow debug APK**.
4. Choose **Run workflow**.
5. Select the branch and press **Run workflow**.

The workflow performs these steps:

- Installs Temurin Java 17.
- Installs the Android SDK command-line tooling.
- Accepts available Android SDK licenses.
- Installs Android platform 35, build-tools 35.0.0, and platform-tools.
- Uses the committed `./gradlew` wrapper, which downloads Gradle 8.7 automatically on the runner.
- Runs `./gradlew --no-daemon --stacktrace assembleDebug`.

## 3. Download the generated APK

After the workflow finishes successfully:

1. Open the completed workflow run in the **Actions** tab.
2. Scroll to the **Artifacts** section.
3. Download **Flow-debug-apk**.
4. Extract the downloaded artifact to obtain `app-debug.apk`.

The workflow uploads this exact Gradle output file:

```text
app/build/outputs/apk/debug/app-debug.apk
```

That is the installable debug APK produced by the `assembleDebug` task. Debug builds are signed with the standard debug key generated by the Android build tools and can be installed on a test Android device after enabling installation from the appropriate source.

## Troubleshooting

- If the workflow does not appear, verify that `.github/workflows/build-apk.yml` is committed at the repository root.
- If the artifact is missing, open the failed **Assemble debug APK with the project Wrapper** step. The workflow is configured with `if-no-files-found: error`, so a missing APK fails clearly rather than producing an empty artifact.
- If GitHub reports a permission issue while uploading, confirm that Actions are enabled for the repository. The workflow only needs read access to repository contents and permission to upload its own artifact.
